1. PROJECT OVERVIEW & OBJECTIVES
================================================================================
Modern transformer models (like BERT, RoBERTa, DistilBERT) achieve state-of-the-
art accuracy in Natural Language Processing, but they operate as "black boxes".
Users and developers typically only see the final prediction (e.g., "POSITIVE 95%"),
without understanding which words or linguistic structures influenced that decision.

The primary objective of this project is to create an end-to-end, production-ready,
and fully explainable sentiment classification system:
- High Accuracy: Fine-tuning a Transformer model on real-world sentiment data.
- Dual-Layer Explainability:
    1) LIME (model-agnostic perturbation explanations)
    2) Multi-Head Self-Attention Heatmaps (model-intrinsic explanations)
- High-Performance API: FastAPI backend with asynchronous request handling.
- Interactive Dashboard: Sleek dark-mode web user interface for real-time
  inference, visualization, and parameter exploration.

2. ARCHITECTURE & ALGORITHMS USED (AND WHY)
================================================================================

2.1 MODEL ARCHITECTURE: DistilBERT (distilbert-base-uncased)
------------------------------------------------------------
Why DistilBERT instead of standard BERT, RoBERTa, or LSTM?
- Efficiency & Speed: DistilBERT has 40% fewer parameters (66 Million vs 110M
  in BERT-base) and runs 60% faster, making it ideal for local CPU execution
  and fast real-time web API inference (<100ms per request).
- Knowledge Distillation: It retains ~97% of BERT's language understanding
  capabilities by training via distillation from a larger teacher model (BERT).
- Bidirectional Context: Unlike traditional Recurrent Neural Networks (LSTMs /
  GRUs) or Bag-of-Words/TF-IDF models, DistilBERT captures deep bidirectional
  context (e.g., handling complex negations like "not bad", "hardly enjoyable").

Model Configuration:
- Base: distilbert-base-uncased
- Layers (Transformer blocks): 6
- Attention Heads per layer: 12 (768 hidden dimension / 12 = 64 per head)
- Classification Head: Linear pre-classifier (768 -> 768) + ReLU + Dropout (0.3)
  + Output Linear Classifier (768 -> 2 classes: NEGATIVE, POSITIVE).
- Attention Implementation: "eager" (required to output full attention weight
  tensors during the forward pass for explainability).

2.2 OPTIMIZATION & LOSS
-----------------------
- Loss Function: Cross-Entropy Loss with Softmax over 2 classes.
- Optimizer: AdamW (Adam with decoupled Weight Decay = 0.01). AdamW prevents
  catastrophic forgetting of pretrained transformer weights compared to
  standard SGD or vanilla Adam.
- Learning Rate Schedule: Linear Warmup (10% of total training steps) followed
  by linear decay down to 0. Peak learning rate = 2.0e-5.
- Gradient Clipping: Max norm = 1.0 (prevents exploding gradients).

3. DATASET DETAILS (AND WHY CHOSEN)
================================================================================

Dataset: Stanford Sentiment Treebank v2 (SST-2)
Hugging Face Path: "stanfordnlp/sst2"

Why SST-2?
1. Gold Standard Benchmark: Part of the official GLUE (General Language
   Understanding Evaluation) benchmark widely used in NLP academic research.
2. Clean Binary Labels: Cleanly labeled sentences from movie reviews:
   - 0: NEGATIVE
   - 1: POSITIVE
3. Realistic Linguistic Phenomena: Contains rich linguistic nuances including
   sarcasm, subtle negations, idioms, and mixed sentiments.

Data Splits:
- Full Training Split: 67,349 sentences
- Full Validation Split: 872 sentences
- Fast-Verification Run: Subsampled to 2,000 training examples and 500 validation
  examples to enable fast iteration on standard CPU while still training a
  strongly generalized checkpoint (achieved >80.6% accuracy in just 1 epoch).

Data Preprocessing Pipeline:
- Regex HTML stripping (`<[^>]+>`)
- URL normalization (replaced with `[URL]`)
- Whitespace collapsing
- WordPiece Tokenization (DistilBertTokenizerFast, max length 128 tokens,
  with padding to max_length and truncation).

4. MODEL TRAINING PIPELINE & METHODOLOGY
================================================================================

The training pipeline is implemented in `train.py` and `src/model.py`:

Step 1: Data Ingestion & Tokenization
- Dataset is loaded and tokenized using HuggingFace Datasets and Fast Tokenizer.
- Custom PyTorch Dataset (`SentimentDataset`) wraps inputs into tensors:
  `input_ids`, `attention_mask`, and `labels`.
- PyTorch `DataLoader` creates mini-batches (batch size 16 for training, 32 for eval).

Step 2: Training Loop
- Model placed in `.train()` mode.
- Mini-batch forward pass -> computes predictions and cross-entropy loss.
- Backward pass (`loss.backward()`).
- Gradient clipping to 1.0 norm.
- Optimizer step (`optimizer.step()`) and scheduler step (`scheduler.step()`).
- Zero gradients (`optimizer.zero_grad()`).

Step 3: Validation & Checkpointing
- Evaluated on validation set at the end of each epoch.
- Best model selection: Evaluates validation accuracy, saves checkpoint if it
  improves upon previous best.
- Outputs saved to disk:
  - `models/distilbert-sentiment/model.safetensors`
  - `models/distilbert-sentiment/config.json`
  - `models/distilbert-sentiment/tokenizer.json`
  - `models/distilbert-sentiment/training_history.json`
  - `reports/training_history.png`

5. EXPLAINABILITY TECHNIQUES (LIME & ATTENTION)
================================================================================

A central feature of this project is answering: "Why did the model classify
this text as Positive or Negative?" Two complementary approaches are used:

5.1 LIME (Local Interpretable Model-Agnostic Explanations)
----------------------------------------------------------
How it works:
1. Takes the user's input sentence.
2. Generates N random perturbations (e.g. 500 variations) by randomly masking
   or removing words from the text.
3. Passes all 500 perturbed sentences through the model to observe changes in
   output probabilities.
4. Fits an interpretable sparse linear surrogate model (Ridge regression)
   weighted by distance from the original text.
5. Produces word importance coefficients:
   - Positive score (>0): The word pushed the prediction towards POSITIVE.
   - Negative score (<0): The word pushed the prediction towards NEGATIVE.

Why LIME?
- True behavioral explanation: Measures direct causal impact of removing words.
- Model-agnostic: Does not rely on model internals, making it trustworthy.

5.2 SELF-ATTENTION WEIGHT VISUALIZATION
---------------------------------------
How it works:
1. The forward pass runs with `output_attentions=True` and `attn_implementation="eager"`.
2. DistilBERT has 6 layers, each with 12 attention heads.
3. We extract the final (6th) layer's attention tensor: shape `(12, seq_len, seq_len)`.
4. Average across all 12 heads to obtain an aggregated token-to-token matrix.
5. We isolate row 0, which corresponds to the special `[CLS]` token. In BERT,
   the `[CLS]` representation is what feeds directly into the classification
   head, so its attention weights indicate which tokens it gathered information from.
6. Special tokens (`[CLS]`, `[SEP]`, `[PAD]`) are filtered out, subword tokens
   (`##`) are reconstructed, and scores are normalized to `[0, 1]`.

Why Attention?
- Model-intrinsic: Shows the exact internal representations learned by the neural network.
- Fast: Calculated directly during the single forward inference pass (no perturbations).

6. API & WEB DASHBOARD IMPLEMENTATION
================================================================================

6.1 BACKEND (FastAPI - `api/main.py`)
- Asynchronous REST API with CORS middleware for seamless integration.
- Endpoints:
  * `GET /` -> Serves the interactive HTML5/CSS3/JS dashboard.
  * `GET /health` -> System health check and model loading status.
  * `POST /predict` -> Fast single prediction (probabilities + confidence).
  * `POST /explain` -> Full inference + LIME word importance + attention scores.
  * `GET /metrics` -> Returns accuracy, F1, precision, recall, and AUC-ROC.
  * `GET /examples` -> Returns pre-curated test sentences for demoing.
  * `GET /docs` -> Interactive OpenAPI / Swagger documentation.
- Lazy Model Loading: The heavy model weights and explainer are loaded once into
  memory on server startup and reused across requests.

6.2 FRONTEND (HTML5, CSS3, Vanilla JS - `frontend/`)
- Dark-mode UI with modern glassmorphism, glowing gradients, and CSS variables.
- Interactive components:
  * Live character counter and input validation.
  * SVG circular confidence gauge animation.
  * Colored horizontal probability bars (Positive vs Negative).
  * Interactive Token Chip heatmap with hover tooltips showing exact attention scores.
  * LIME horizontal divergence bar chart (green for positive, red for negative).
  * Example picker modal with instant auto-population and analysis.

7. BUGS IDENTIFIED & FIXES APPLIED DURING DEVELOPMENT
================================================================================

During testing and verification of the initial codebase, several critical bugs
and edge-cases were identified and fixed:

Bug 1: Label Key Type Mismatch in `src/explainer.py`
- Problem: The code queried `self.model_cfg["labels"]["0"]` (string key), but
  PyYAML parsed integer keys from `config.yaml` (`{0: 'NEGATIVE', 1: 'POSITIVE'}`).
  This caused an immediate `KeyError: '0'` crash whenever `/explain` was called.
- Fix: Normalized all label dictionary keys to integers:
  `_labels = {int(k): v for k, v in self.model_cfg["labels"].items()}`.

Bug 2: Deprecated Hugging Face `trust_remote_code=True` in `src/data_loader.py`
- Problem: Modern versions of Hugging Face `datasets` throw an error if
  `trust_remote_code=True` is supplied for standard datasets.
- Fix: Removed the deprecated argument from all `load_dataset` calls.

Bug 3: Hugging Face Dataset URI Schema (`sst2` -> `stanfordnlp/sst2`)
- Problem: Recent Hugging Face Hub library changes enforce the `namespace/name`
  convention. Passing `"sst2"` directly resulted in an invalid URI error.
- Fix: Updated `config.yaml` and data loader to use `"stanfordnlp/sst2"`.

Bug 4: DistilBERT Attention Eager Implementation in `src/model.py`
- Problem: PyTorch 2.x defaults DistilBERT to SDPA (Scaled Dot-Product Attention),
  which does not support `output_attentions=True` and threw a warning/silent failure.
- Fix: Set `attn_implementation="eager"` in both initial model construction and
  the `SentimentModel.load()` classmethod.

Bug 5: Windows Console Encoding in `evaluate.py`
- Problem: Unicode emojis (`📊`, `🧪`, `🟢`, `🔴`) triggered a `UnicodeEncodeError`
  under the Windows default `cp1252` console encoding.
- Fix: Replaced raw terminal emojis with ASCII indicators (`[RESULTS]`, `[+]`, `[-]`).

Bug 6: CSS `[hidden]` Specificity Bug in Web Dashboard
- Problem: `.modal-overlay { display: flex; }` in `style.css` had higher specificity
  than the browser user-agent's `[hidden] { display: none; }`. As a result, the
  "Example Sentences" modal popped up on page load and could not be closed.
  The error toast in the corner was also stuck visible.
- Fix:
  1) Added `[hidden] { display: none !important; }` in `frontend/style.css`.
  2) Added an `Escape` key event listener in `frontend/app.js` for easy dismissal.

Bug 7: Missing Git Tracking Hygiene
- Problem: Large PyTorch `.safetensors` model files (~268MB) would exceed GitHub's
  100MB file limit if committed accidentally, while `__pycache__` cluttered git status.
- Fix: Created `.gitignore` ignoring large weights and caches while retaining
  lightweight model configuration and tokenizer JSON files.

9. HOW TO RUN, TEST, AND REPRODUCE THE PROJECT
================================================================================

Prerequisites:
- Python 3.10 or 3.11 installed.

Step 1: Install Dependencies
    pip install -r requirements.txt

Step 2: Run Smoke Test (Module Verification)
    python smoke_test.py

Step 3: Train the Model
    python train.py
    (To train on full data with 3 epochs, edit config.yaml and set
     max_train_samples: null, max_val_samples: null, epochs: 3)

Step 4: Evaluate the Model & Generate Charts
    python evaluate.py --skip-lime
    (Or omit --skip-lime to generate full LIME example charts)

Step 5: Start the API & Web Dashboard
    python -m uvicorn api.main:app --reload --port 8000

Step 6: Access the Application
    Open your web browser and navigate to:
    - Dashboard: http://localhost:8000
    - Swagger API Docs: http://localhost:8000/docs
    - Health Check: http://localhost:8000/health
